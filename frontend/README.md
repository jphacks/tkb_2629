# TKB 2629 frontend

Expo + React Native + TypeScript で構成したアプリのひな型です。

Node.js 22.13 以上（推奨: 24 LTS）が必要です。

## 起動

```bash
npm install
npm start
```

バックエンドの URL は `.env` の `EXPO_PUBLIC_API_URL` で変更できます。Android エミュレーターからホスト PC の API に接続する場合は、通常 `http://10.0.2.2:8000` を指定してください。

## 構成

- `App.tsx`: 画面のエントリーポイント
- `src/lib/api.ts`: API クライアント
- `src/types/user.ts`: ユーザー型

「本棚」から「本を追加する」を開くと、Google Booksのタイトル検索結果を表示します。
候補をタップするとGoogle BooksのIDをバックエンドで再取得し、共有書誌を本棚へ追加します。
バックエンドでは認証・SMTP設定と最新のDBマイグレーションを適用し、登録・メール確認・ログインを行ってください。
ログイン・登録・パスワード再設定のパスワード欄は初期状態で非表示です。右端の目のボタンで欄ごとに表示・非表示を切り替えられます。切り替えても入力内容は維持し、送信中は操作を無効にします。
関連テストは `node --test tests/passwordVisibility.test.cjs` で実行できます。

### ホームの読了タワー

「読んだ本」は本棚の全ページを取得し、読了回数（再読も1冊）で集計します。
最新回が読書中なら `latest_iteration - 1`、読了済みなら `latest_iteration` を加算します。
再読は前の回の読了後にしか開始できない既存APIのルールを利用し、本ごとの履歴取得は行いません。
本棚から削除した本は集計対象外です。ホームを開き直すと最新の冊数を取得します。
読み込み中や取得失敗を0冊と表示せず、失敗時は再読み込みできます。
タワーは達成感を表す模式図です。10冊までは1冊1段、それ以降は対数的に圧縮し、
手前2列と冊数に応じた奥2列・合計最大32冊の描画で成長させ、背後に本を落とす表現は廃止しました。
上限後も正確な冊数は増え続けます。色は再描画しても変わらない順序です。
本は上面・背表紙・ページ断面を描き分け、ハイライト・足元の影で立体感を出します。
幅・厚さ・表紙色を変えつつ、共通の投影座標で下の本の天面と上の本の底面を接触させます。
本ごとの回転や隙間は設けず、上に載る本全体の重心が支持面内に収まる配置です（物理シミュレーションではありません）。
上の本が少し大きい組み合わせも含めます。奥の山は手前より小さく、接地位置を上にずらし、奥から手前の順に描画します。
冊数は3桁区切り・1行の自動縮小で表示し、ホーム全体をスクロール可能にしています。
ホームのサジェスト・感想カードの仮データは今回の対象外です。
関連検証: `node --test tests/reading.test.cjs`。
Expo Goなどの開発ビルドでは「開発用・タワーの表示確認」で0・1・10・100・1000冊を切り替えられます。
これは表示だけのプレビューで、読了・本棚データは書き換えません。
「実際の冊数に戻す」かホームを開き直すと解除されます。取得エラーはプレビュー中も表示します。
`__DEV__` がfalseのリリースビルドには確認用UIを表示しません。

### 名前（アカウント・公開感想で共通）

アカウント → 名前を設定・変更、またはアカウント設定 → 名前から、共通の名前を確認・変更できます。
新規登録は「名前（他の読者にも表示）」の1項目だけを使い、本名でなくてもよいことと公開範囲を説明します。
名前をtrimして1〜100文字と検証し、登録APIへ `name_is_public: true` を送ります。
既存の公開名があれば採用し、未設定の場合は空欄と案内を表示します。以前の登録名・メールアドレスを自動転用しません。
アカウント画面も公開プロフィールAPIから最新の名前を取得し、保存後に戻ると反映します。
古いログインセッションの名前は代用せず、取得中・エラー・未設定を区別して表示します。
前後の空白を除いて1〜100文字で保存できます。取得失敗は再読み込み、保存失敗は入力を保持して再試行できます。
保存中は入力・戻る・下部タブ操作を無効にします。
保存するとアカウント名も統一され、既存の公開感想にも新しい名前が表示されます。
初回保存まで公開感想一覧には掲載されません。設定後に未設定へ戻す機能はありません。
独立した他の読者のプロフィール閲覧・写真・公開前の強制設定はまだ提供しません。
バックエンドの名前統一API（#34）と `0012_public_display_name` 適用が必要です。追加のDB移行はありません。
名前の表示イメージには、丸い背景の本のデフォルトアイコンと保存済みの名前を並べます。
未設定の場合は「名前は未設定」と表示し、編集中の名前は保存成功後に反映します。
画像のアップロードやアイコン変更はまだ提供しません。
関連テストは `node --test tests/publicProfile.test.cjs` で実行します。

### 感想の公開設定

栞の入力画面で「他の読者に公開する」を切り替え、通常の保存ボタンまたはスワイプで保存します。
新規はOFF、既存は保存済みの設定を表示します。現在の閲覧専用画面では設定も変更できません。
バックエンドの `0010_review_visibility` 適用が必要です。
公開ONで保存した感想は、公開用表示名が設定済みなら同じ本の公開感想一覧に掲載されます。
本文保存後に設定保存が失敗した場合は、本文が保存済みであることを表示します。
入力を変えずに再度保存すると、本文の再保存・再分析をせず設定を再送します。
設定だけの変更でも本文の再保存・再分析は行いません。
公開スイッチは1.2倍で表示します。上スワイプは24以上の移動で動き始め、
104以上の移動で保存します（React Nativeのレイアウト単位）。短い高速スワイプでは保存しません。
設定保存は本文保存と別リクエストのため、既に公開中の感想を編集して非公開にする場合、
本文更新から非公開設定の確定までの間は保存済みの公開設定が維持されます。

```bash
node --test --test-skip-pattern="app keeps bookmark|back follows the actual entry" tests/bookmark.test.cjs
```

既存のAppナビゲーション2テストは認証導入前のモックのため失敗し、上記では対象外にしています。

### 感想のネタバレ設定

公開スイッチの下に「ネタバレを含む」を表示します。新規はON、既存は保存済みの値です。
両スイッチのラベルは「今の感想」と同じ共通ラベルを使用します。
栞内部は内容が収まらない場合にスクロールでき、下の保存ボタンまで確認できます。
内部からのスワイプ保存は、末尾に到達した後の新しい上スワイプで行います。
上部のスワイプ領域からの保存は引き続き使用できます。
下端のスワイプ案内はスクロール外に固定し、本文のスクロール位置によらず上スワイプできます。
ネタバレ設定下の色の横棒は表示せず、栞の背景色は維持します。
文字数は「今の感想」の右に `（入力文字数 / 140文字）` と表示します。
色の呼び方は「感想の色」に統一します。栞の入力・保存完了画面では通常の色ラベルは表示せず、
準備中・失敗・仮の色の案内は維持します。
公開範囲とは独立して選択し、保存ボタン・スワイプで保存します。閲覧専用時と保存中は変更できません。
バックエンドの `0011_review_spoilers` 適用が必要です。
設定のみの変更では本文を再保存・再分析しません。本文、ネタバレ設定、公開設定の順に保存し、
途中で失敗したら成功画面に進まずエラーを表示します。同じ画面で再保存すると、
既に成功した本文・設定は再送せず、失敗した設定から再試行します。
各保存は別リクエストであり、全体を一括で確定・取り消すものではありません。
みんなのしおりでは、この設定と閲覧者の読書位置に応じて本文と感情色を初期非表示にします。

### 感想へのリアクション

感想の一覧で本文を表示すると、ハートの「共感した」・電球の「なるほど」・目の「気になる」を表示します。
最新1件のプレビューや本文を隠している感想には表示せず、一覧を開く・本文を表示する操作後に取得します。
自分の公開感想にも付けられます。1人1種類で、選択済みをもう一度押すと取り消し、別の種類なら切り替えます。
件数と自分の選択をAPIから取得し、選択中は塗りアイコン・背景・読み上げの選択状態で示します。
取得・送信中は3つとも操作不可です。成功前に件数や選択を変えません。
失敗はエラーを表示し、「リアクションを再読み込み」でサーバーの最新状態を確認してから再操作できます。
再読み込み前の件数は最後に確認できた値であり、失敗した操作がサーバーに届いていた可能性があります。
一覧を閉じて再度開く・非表示にして再度本文を表示する場合も再取得します。自動通知・定期更新・押した人の一覧はありません。
本文が表示されたカードごとに取得するため、1回20件の一覧なら最大20回の追加GETが発生します。
バックエンドの `0013_review_reactions` まで移行が必要です。非公開化・公開用表示名の解除後の操作は404になります。
APIと保持条件の詳細は [リアクションAPI](../fastapi/docs/review-reactions.md) を参照してください。
`node --test tests/publicReviews.test.cjs` でクライアントの契約・表示条件・切り替え・エラー・遅延応答を検証します。

### みんなのしおり・全件分布

本の詳細の「しおり一覧」で「自分のしおり／みんなのしおり」を切り替えます。
自分のしおりは従来の実データのタイムライン・5件ずつの一覧・閲覧編集への遷移を維持します。
みんなのしおりはサンプルを廃止し、Google Booksから追加した本の公開感想を表示します。
手動登録の本は対象外の案内を表示します。自分側の読み込み失敗時でも、みんな側は利用できます。

`GET /catalog/books/{google_books_id}/reviews/distribution` で全公開対象のページ別件数を取得します。
先頭20件から推測せず、自分・過去の読書回も含む全件の集計を使います。
左端は総ページ・右端は0ページです。区間の下は100%、90%、…、10%の10刻みで表示します。
30%は20〜30%の区間です。押すと対応する具体的な開始〜終了ページと件数を表示します。
ページ境界は切り捨てで計算し、全ページを重複・欠落なく割り当てます。
10ページ未満の本で割当ページがない区間は操作不可です。
画面内の説明は操作案内と非表示理由を中心に短くし、詳細な仕様はこの文書に記載します。
画面幅によらず10%刻みの10区間で表示します。
分布は淡い灰色のなだらかな曲線と塗りで表示し、選択範囲は枠で強調します。
曲線は範囲別の感想件数を滑らかにつないだ目安であり、ページごとの正確な密度を表すものではありません。
選択範囲の見出しに正確な公開感想件数を表示します。曲線に各感想の色を混ぜません。
薄い背景は未読を含む範囲で、未読部分の件数も表示します。色だけでなく数字・選択枠・読み上げラベルも使います。
範囲を選ぶと、両端を含む `page_start` / `page_end` で公開感想を読み込みます。
選択を変えるとoffset・開いた本文をリセットし、古いリクエストは新しい範囲に反映しません。
更新ボタンは置かず、「みんなのしおり」を開き直すたびに本の情報・全件分布を再取得します。
範囲を選ぶと、その範囲の感想を取得します。取得失敗時の再試行ボタンは維持します。
ページ番号を指定すると、そのページのみの感想を取得できます（1〜総ページの整数）。
共通枠内に「［ページ番号］ページの［感想を読む］」を並べ、一組の操作として表示します。
選択範囲のページ表記は、周囲の見出しより少し濃い文字にします。
自分のしおりの感想と横並びにした右側の吹き出しアイコンからも、番号を引き継いで切り替えられます。
アイコンは44×44のタップ領域を持ち、読み上げでは「○ページのみんなの感想を読む」と伝えます。
同じページ番号でも版や表示形式によって文章が異なる場合があります。
現APIでは自分以外の正確な判定ができないため、「自分以外」の切り替えはまだ提供しません。
総ページ数が不明・不正、総ページ数を超えるしおり、集計結果の不整合は空分布にせずエラーを表示します。

認証必須の `GET /catalog/books/{google_books_id}/reviews` を使い、公開用表示名・本の丸い
デフォルトアイコン・ページ・投稿者の読書回・ネタバレ設定を表示します。
登録名・メールアドレス・投稿者のユーザーIDは取得しません。
同じ表示名が同じ投稿者であるとは限りません。

ネタバレあり、未読ページ、読書位置が不明な感想の本文と感情色は、画面やアクセシビリティツリーに
描画しません。「この感想を表示する」でその1件だけ開き、「この感想を隠す」で戻せます。
色はユーザーの固定色ではなく、その感想の解析結果です。12pxの丸いアクセントだけに使い、
実AI・仮の色・解析待ち・失敗・結果未確認の案内を添えます。分布全体を感情色で塗りません。
現在の読書回の進捗で判定し、読了済みなら総ページ数までを既読扱いにします。
再読中は過去の読了にかかわらず今回の進捗で隠します。ネタバレありは読了後も隠します。
これは表示制御であり、公開本文のアクセス制限ではありません。

通常は選択範囲の最新1件だけを3行までプレビューします。投稿者ではなく感想1件が単位です。
プレビューを押すと画面下からコメントパネルを開き、内部でスクロールできます。
パネルには閉じるボタンがあり、Androidの戻るでも閉じられ、元の分布と選択範囲は維持します。
閉じると開いたネタバレ本文を隠し直します。
パネルでは20件ずつ更新日時の新しい順に表示し、「さらに読み込む」で追加します。
追加取得失敗時は既存一覧を残して再試行でき、連打による重複リクエストを防ぎます。
みんなのしおり内には重複した更新ボタンを置きません。
公開設定の変更は再取得で反映します。投稿更新によってページ間の位置が変わる場合があり、
追加取得時の同一感想IDは重複表示しません。
初期読み込み・0件・取得失敗と再試行に対応します。分布と本文は別のAPIのため、同時更新でずれる場合があります。
リアクション・DM・フォローは対象外で、未実装ボタンも置きません。バックエンドの分布・範囲・色対応APIが必要です。

## 画面遷移

画面遷移は `src/screens/types.ts` の `Navigate` 型を共有します。
本の詳細・編集へは `{ name: 'book-detail', bookId }` のように対象の本のIDを渡します。
本棚で選択したIDは、詳細→編集→詳細の遷移でも保持します。
それ以外の画面は従来どおり画面名の文字列でも遷移できます。

本棚は一度でも読了した本だけを表示します。初読中の本は対象外で、再読中の本は本棚にも残ります。
本一覧を100件ずつ最後まで取得し、対象の本の読書履歴から最後の読了日を取得して、新しい順・端末の現地時間の月別で整理します。
再読を完了すると最新の読了日の月へ移り、同じ本は1枚だけ表示します。読了日がない・不正な場合は「読了日不明」として末尾にまとめます。
キーワード検索は書名・著者・自分の全読書回の感想本文が対象です。全角英数字・英字の大小を正規化した部分一致で、空白区切りの複数語はAND検索します。
感想に一致する場合は読書回・ページ・抜粋を表示します。月別表示は検索中も維持します。
読書履歴と各読書回の感想（ページネーションを含む）を取得するため、本や感想が多いと初期読み込みに時間がかかります。検索入力ごとのAPI呼び出しはありません。
本棚が空の場合と、キーワードに一致する本がない場合は別の案内を表示します。
本棚右上の＋は、下部タブの「本を探す」と同じ画面を開きます。
履歴・感想を含めて取得に失敗した場合は、部分的な結果を表示せずエラーを表示し、「再試行」で先頭から取得し直します。
関連テストは `node --test tests/bookshelf.test.cjs` で実行できます。

本の詳細は `GET /books/{bookId}` から書名・著者・読書進捗を取得します。
取得中は読み込み表示、失敗時はエラーと再試行ボタンを表示します。
本棚と同様に、詳細の取得にはバックエンドの認証設定が必要です。

詳細内の「自分のしおり」はAPIから取得した実データです。
他の人のしおり・感情分析・画面全体のアクセント色はサンプルであることを明記しています。
編集画面は準備中の案内と「本の詳細へ戻る」ボタンだけを表示し、本の情報は変更・保存できません。
アカウント設定にはログイン中の名前・メールを表示し、パスワード再設定とログアウトを利用できます。
プロフィール変更・読書設定など未対応の項目には「準備中」を表示し、タップ・スイッチ操作はできません。

「今読んでいる本」は本棚APIを100件ずつ最後まで取得し、読書中の本だけを表示します（`src/lib/readingBooks.ts`）。
カードを押すとその本の詳細へ、カード内の「しおりを追加」を押すと最新の読書回でしおり入力画面へ遷移します。
右上の＋と、読書中の本がない場合の「本を追加する」は、下部タブの「本を探す」と同じ画面を開きます。取得失敗時には再試行できます。
関連テストは `node --test tests/reading.test.cjs` で実行できます。
詳細の読書状態・進捗はAPIの値を使い、読了済みの場合は進捗バーを表示しません。
進捗は「◯ / ◯ ページ（◯% 読了）」の1行で表示します。◯%は記録したしおりの最も先のページから計算します。

読書中の本の詳細には「読了にする」ボタンがあります。確認ダイアログで「読了にする」を選ぶと
`POST /books/{bookId}/iterations/{iteration}/complete` で最新の読書回を読了にし、詳細を再取得します。
100%に達しても自動では読了にしません。読了後はその読書回のしおりを追加・編集できません。
既に読了済み（409）の場合は詳細を再取得し、その他の失敗時はエラーを表示して再度押せます。
関連テストは `node --test tests/complete.test.cjs` で実行できます。

読了した本の詳細には「もう一度読む」を表示します。確認後、既存の `POST /books/{bookId}/iterations` で次の読書回を開始して詳細を再取得します。
開始後は「2回目・読書中」などの状態と0ページの進捗を表示し、新しい読書回にしおりを記録します。過去の読書回・しおりは削除しません。
再読中は本棚にも残り、「今読んでいる本」にも表示されます。読書中の本には再読開始ボタンを出しません。
開始処理中の重複送信を防ぎ、失敗時（409を含む）はエラーを表示して再試行できるようにします。

本の詳細には「読書の記録」として、本棚に追加した日（1回目の開始日）と読書回ごとの期間を表示します（`GET /books/{bookId}/iterations`）。
取得失敗時はエラーと「読書の記録を再試行」を表示します。

「本を探す」「本の新規追加」の検索結果では、誤操作防止のためカード本体では追加せず、ボタンから操作します。
自分の本棚にある本（Google BooksのIDが一致する本）には、「2026/10/20 追加・読書中」「2026/10/24 読了」
「2回目を読書中（これまで1回読了）」などの状態を表示します。追加した直後の本にも表示されます。
すべての検索カードには「詳細を見る」と「タップして本棚に追加」を縦に並べ、間隔16px・タッチ領域の高さ48px以上を確保します。追加済みの場合は紫背景・白文字の「追加済み」として追加操作を無効にします。
「詳細を見る」では追加せず、未追加の本は書名・著者・ページ数のプレビューを開きます。
プレビューからも追加でき、左上の戻る矢印で検索内容を維持して戻れます。追加済みの本は従来の本の詳細を開きます。
追加成功後は自動で本の詳細を開きます。左上の戻る矢印で、検索結果から追加した場合は検索結果、プレビューから追加した場合はプレビューへ戻ります。
検索から開いた本の詳細でしおりを記録した場合は、しおり画面左上の矢印で同じ本の詳細に戻り、最新の進捗・しおりを取得します。保存中は戻る矢印を無効にします。
左上の矢印は開いてきた経路に従って戻ります。「今読んでいる本」→詳細→しおりの場合は詳細へ、一覧やホームから直接しおりを開いた場合は元の一覧やホームへ戻ります。下部タブで別の画面を選んだ場合は、それ以前の戻り履歴をリセットします。
本棚の取得に失敗した場合は状態を表示せず、検索・追加はそのまま使えます。
未追加の本の他の人の感想の分布はバックエンドの対応が必要なため未実装で、プレビューに準備中と表示します。
関連テストは `node --test tests/history.test.cjs` で実行できます。

## しおりの記録

しおり入力画面は、「今読んでいる本」のカードまたは読書中の本の詳細から、本ID・読書回を指定して開きます。
ホームのしおりボタンは、読書中の本が1冊ならその本の入力画面を直接開き、0冊・2冊以上・取得失敗時は「今読んでいる本」を開きます。
本を指定せずに入力画面を開いた場合は、「今読んでいる本」で本を選ぶよう案内します。
入力画面でも最新の読書状態を確認し、読了済み・過去の読書回への保存を防ぎます。

1. ページを1〜総ページ数の範囲で入力します。入力が350ms止まると自動で読み込みます。
2. `GET /books/{bookId}/pages/{page}/review?iteration={iteration}` で既存の感想と色を確認します。
   同じ読書回の同じページには1件だけ保存でき、既存の場合は更新として本文を読み込みます。
   ページを変えると編集欄が切り替わるため、入力中の感想は先に保存してください。
3. 前後の空白を除いて1〜140文字の感想を入力し、リボン周辺またはカードの見出しを上にスワイプするか、保存ボタンを押します。
   リボン周辺は画面コンテンツ幅・高さ104の判定領域です。通常はカード内部のスクロールを無効にし、カード全体の上スワイプで保存します。
   キーボード表示中だけ内部スクロールを有効にし、最下部で指を置き直した上スワイプを保存操作にします。キーボードを閉じると内部の表示位置を先頭へ戻して固定します。
   最下部に到達するまでのスクロール量は保存判定に含めません。保存中・閲覧専用ではスワイプ保存を無効にします。
   上方向64以上で保存します。リボン周辺・見出しでは上方向24以上かつ速度0.6以上のフリックでも保存できます（距離はReact Nativeのレイアウト単位）。
   カード下側はスクロールのレスポンダーを奪わず、最下部から始まるタッチの移動と終了を追跡して保存します。キャンセルされたタッチは保存しません。画面内には操作説明を追加せず、従来のスワイプ案内だけを表示します。
   判定未達では元に戻り、判定達成では元に戻さずその位置で保存を待ちます。入力不正・保存失敗時は元に戻し、エラーを表示します。
4. `PUT` の保存成功後だけ、返却された `color_code` を使って完了演出を表示します。退場アニメーションはネイティブドライバーで320ms、画面の高さに応じて上へ移動します。
   新規・更新ともに完了後は上部の見出しと戻る矢印を隠し、成功メッセージと「本の詳細へ」「続けて他のページの感想も書く」を中央に表示します。
   続けて記録すると同じ本・読書回の入力をリセットし、見出しと戻る矢印を再表示します。
   失敗時は入力を保持し、エラーを表示して再試行できます。保存中の二重送信は防止します。
5. 「本の詳細へ」で戻ると詳細を再取得し、保存されたページに応じた進捗を表示します。

詳細の「自分のしおり」は `GET /books/{bookId}/reviews?iteration={iteration}&limit=100&offset=0`
をページングして取得します。保存後に詳細へ戻ると、感想と各しおりの色を再取得します。
解析状態とsourceから、実AIによる色・AI未接続の仮色・解析待ち・解析失敗を区別します。
同じ感想や似た感情の解析では同じ色になる場合があります。色をランダムには変更しません。
感情グラフの実データ化は未対応です。
ネタバレ設定・他の人への公開は未対応です。

### 自分のしおりの閲覧・編集

数直線の点または感想行をタップすると、本ID・読書回・ページ番号を渡して栞を開きます。
ページ番号の再入力なしで感想と色を自動取得します。読書中の最新回は編集でき、
読了済み・過去の読書回は閲覧専用です（保存ボタン・スワイプ保存・本文編集は無効）。

数直線は左端がAPIの `current_page`（読んだ最遠ページ）、右端が0ページです。
近接した栞は最低56pxの間隔を確保するよう区間を伸ばし、この数直線部分だけを横に
スクロールできます。このため画面上の距離は厳密なページ比率ではありません。
タイムラインは常に全件表示し、その下の感想行はページ順で5件ずつ表示します。
9件なら「1/2」「2/2」に分け、「前へ」「次へ」で切り替えます。

関連テストは `node --test tests/bookmark.test.cjs`、型チェックは `npm run typecheck` で実行できます。

## ログイン

起動時にログインを復元し、未ログイン時はログイン・登録・メール確認・パスワード再設定画面だけを表示します。
認証画面には下部ナビゲーションを表示しません。APIはJWTを自動付与し、401時に一度だけ更新して再試行します。
アカウント画面の名前・メールはログイン中の情報を表示します。設定画面からログアウトできます。
登録・再設定のパスワードは12〜128文字です。メールに届いた確認トークンを画面へ貼り付けます。

Web版のアクセストークンはメモリ、リフレッシュトークンはAPIのHttpOnly Cookieに保存します。
Webの本番配置ではフロントとAPIを同一サイトに置いてください（例: `app.example.com` と `api.example.com`）。
CookieはSameSite=Laxで、ブラウザの異なるサイトへのCookie制限を前提とした設計です。
開発時はバックエンドを `APP_ENV=development` にし、フロントとAPIで `localhost` / `127.0.0.1` を混在させないでください。
スマホ版はリフレッシュトークンを `expo-secure-store` に保存します。依存関係の追加後は `npm install` を行い、
独自の開発ビルドを使っている場合はネイティブアプリを再ビルドしてください。
SMTP・秘密鍵・マイグレーションは [認証設定](../fastapi/docs/authentication.md) を参照してください。

しおり追加画面の公開・ネタバレ設定は、ヘッダー右上の「設定」モーダルからページ入力前に変更できます。
新規ページ入力時も選択値を保持し、しおり保存時に反映します。既存のしおりを開く場合は保存済み設定を読み込みます。
しおり内部と感想欄はスクロールせず、入力欄以外をタップするとキーボードが閉じます。
