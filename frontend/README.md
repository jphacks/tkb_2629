# TKB 2629 frontend

Expo + React Native + TypeScript で構成したアプリのひな型です。

Node.js 22.13 以上（推奨: 24 LTS）が必要です。

## 起動

```bash
npm install
npm start
```

バックエンドの URL は `.env` の `EXPO_PUBLIC_API_URL` で変更できます。Android エミュレーターからホスト PC の API に接続する場合は、通常 `http://10.0.2.2:8000` を指定してください。

## 構成

- `App.tsx`: 画面のエントリーポイント
- `src/lib/api.ts`: API クライアント
- `src/types/user.ts`: ユーザー型

「本棚」から「本を追加する」を開くと、Google Booksのタイトル検索結果を表示します。
候補をタップするとGoogle BooksのIDをバックエンドで再取得し、共有書誌を本棚へ追加します。
バックエンドでは認証・SMTP設定と最新のDBマイグレーションを適用し、登録・メール確認・ログインを行ってください。
ログイン・登録・パスワード再設定のパスワード欄は初期状態で非表示です。右端の目のボタンで欄ごとに表示・非表示を切り替えられます。切り替えても入力内容は維持し、送信中は操作を無効にします。
関連テストは `node --test tests/passwordVisibility.test.cjs` で実行できます。

### API接続の確認

Expo Goを実機で利用する場合、`localhost` はスマートフォン自身を指します。
`frontend/.env` の `EXPO_PUBLIC_API_URL` に、PCのLANアドレスとbackendのポート
（例: `http://192.168.1.10:8000`）を指定し、Expoを再起動してください。
Expoの配信ポートとbackendのポートは別です。

開発時はAPIレスポンスのURL・HTTPステータス・Content-Typeを `[API]` ログに出します。
レスポンス本文はログに出しません。JSON以外の応答や壊れたJSONは、
接続先情報を含むエラーとして表示します。

## 画面遷移

画面遷移は `src/screens/types.ts` の `Navigate` 型を共有します。
本の詳細・編集へは `{ name: 'book-detail', bookId }` のように対象の本のIDを渡します。
本棚で選択したIDは、詳細→編集→詳細の遷移でも保持します。
それ以外の画面は従来どおり画面名の文字列でも遷移できます。

本棚は一度でも読了した本だけを表示します。初読中の本は対象外で、再読中の本は本棚にも残ります。
本一覧を100件ずつ最後まで取得し、対象の本の読書履歴から最後の読了日を取得して、新しい順・端末の現地時間の月別で整理します。
再読を完了すると最新の読了日の月へ移り、同じ本は1枚だけ表示します。読了日がない・不正な場合は「読了日不明」として末尾にまとめます。
キーワード検索は書名・著者・自分の全読書回の感想本文が対象です。全角英数字・英字の大小を正規化した部分一致で、空白区切りの複数語はAND検索します。
感想に一致する場合は読書回・ページ・抜粋を表示します。月別表示は検索中も維持します。
読書履歴と各読書回の感想（ページネーションを含む）を取得するため、本や感想が多いと初期読み込みに時間がかかります。検索入力ごとのAPI呼び出しはありません。
本棚が空の場合と、キーワードに一致する本がない場合は別の案内を表示します。
本棚右上の＋は、下部タブの「本を探す」と同じ画面を開きます。
履歴・感想を含めて取得に失敗した場合は、部分的な結果を表示せずエラーを表示し、「再試行」で先頭から取得し直します。
関連テストは `node --test tests/bookshelf.test.cjs` で実行できます。

本の詳細は `GET /books/{bookId}` から書名・著者・読書進捗を取得します。
取得中は読み込み表示、失敗時はエラーと再試行ボタンを表示します。
本棚と同様に、詳細の取得にはバックエンドの認証設定が必要です。

詳細内の「自分のしおり」はAPIから取得した実データです。
他の人のしおり・感情分析・画面全体のアクセント色はサンプルであることを明記しています。
編集画面は準備中の案内と「本の詳細へ戻る」ボタンだけを表示し、本の情報は変更・保存できません。
アカウント設定にはログイン中の名前・メールを表示し、パスワード再設定とログアウトを利用できます。
プロフィール変更・読書設定など未対応の項目には「準備中」を表示し、タップ・スイッチ操作はできません。

「今読んでる本」は本棚APIを100件ずつ最後まで取得し、読書中の本だけを表示します（`src/lib/readingBooks.ts`）。
カードを押すとその本の詳細へ、カード内の「しおりを挟む」を押すと最新の読書回でしおり入力画面へ遷移します。
右上の＋と、読書中の本がない場合の「本を追加する」は、下部タブの「本を探す」と同じ画面を開きます。取得失敗時には再試行できます。
関連テストは `node --test tests/reading.test.cjs` で実行できます。
詳細の読書状態・進捗はAPIの値を使い、読了済みの場合は進捗バーを表示しません。
進捗は「◯ / ◯ ページ（◯% 読了）」の1行で表示します。◯%は記録したしおりの最も先のページから計算します。

読書中の本の詳細には「読了にする」ボタンがあります。確認ダイアログで「読了にする」を選ぶと
`POST /books/{bookId}/iterations/{iteration}/complete` で最新の読書回を読了にし、詳細を再取得します。
100%に達しても自動では読了にしません。読了後はその読書回のしおりを追加・編集できません。
既に読了済み（409）の場合は詳細を再取得し、その他の失敗時はエラーを表示して再度押せます。
関連テストは `node --test tests/complete.test.cjs` で実行できます。

読了した本の詳細には「もう一度読む」を表示します。確認後、既存の `POST /books/{bookId}/iterations` で次の読書回を開始して詳細を再取得します。
開始後は「2回目・読書中」などの状態と0ページの進捗を表示し、新しい読書回にしおりを記録します。過去の読書回・しおりは削除しません。
再読中は本棚にも残り、「今読んでる本」にも表示されます。読書中の本には再読開始ボタンを出しません。
開始処理中の重複送信を防ぎ、失敗時（409を含む）はエラーを表示して再試行できるようにします。

本の詳細には「読書の記録」として、本棚に追加した日（1回目の開始日）と読書回ごとの期間を表示します（`GET /books/{bookId}/iterations`）。
取得失敗時はエラーと「読書の記録を再試行」を表示します。

「本を探す」「本の新規追加」の検索結果では、誤操作防止のためカード本体では追加せず、ボタンから操作します。
自分の本棚にある本（Google BooksのIDが一致する本）には、「2026/10/20 追加・読書中」「2026/10/24 読了」
「2回目を読書中（これまで1回読了）」などの状態を表示します。追加した直後の本にも表示されます。
すべての検索カードには「詳細を見る」と「タップして本棚に追加」を縦に並べ、間隔16px・タッチ領域の高さ48px以上を確保します。追加済みの場合は紫背景・白文字の「追加済み」として追加操作を無効にします。
「詳細を見る」では追加せず、未追加の本は書名・著者・ページ数のプレビューを開きます。
プレビューからも追加でき、左上の戻る矢印で検索内容を維持して戻れます。追加済みの本は従来の本の詳細を開きます。
追加成功後は自動で本の詳細を開きます。左上の戻る矢印で、検索結果から追加した場合は検索結果、プレビューから追加した場合はプレビューへ戻ります。
検索から開いた本の詳細でしおりを記録した場合は、しおり画面左上の矢印で同じ本の詳細に戻り、最新の進捗・しおりを取得します。保存中は戻る矢印を無効にします。
左上の矢印は開いてきた経路に従って戻ります。「今読んでる本」→詳細→しおりの場合は詳細へ、一覧やホームから直接しおりを開いた場合は元の一覧やホームへ戻ります。下部タブで別の画面を選んだ場合は、それ以前の戻り履歴をリセットします。
本棚の取得に失敗した場合は状態を表示せず、検索・追加はそのまま使えます。
未追加の本の他の人の感想の分布はバックエンドの対応が必要なため未実装で、プレビューに準備中と表示します。
関連テストは `node --test tests/history.test.cjs` で実行できます。

## しおりの記録

しおり入力画面は、「今読んでる本」のカードまたは読書中の本の詳細から、本ID・読書回を指定して開きます。
ホームのしおりボタンは、読書中の本が1冊ならその本の入力画面を直接開き、0冊・2冊以上・取得失敗時は「今読んでる本」を開きます。
本を指定せずに入力画面を開いた場合は、「今読んでる本」で本を選ぶよう案内します。
入力画面でも最新の読書状態を確認し、読了済み・過去の読書回への保存を防ぎます。

1. ページを1〜総ページ数の範囲で入力します。入力が350ms止まると自動で読み込みます。
2. `GET /books/{bookId}/pages/{page}/review?iteration={iteration}` で既存の感想と色を確認します。
   同じ読書回の同じページには1件だけ保存でき、既存の場合は更新として本文を読み込みます。
   ページを変えると編集欄が切り替わるため、入力中の感想は先に保存してください。
3. 前後の空白を除いて1〜140文字の感想を入力し、リボン周辺またはカードの見出しを上にスワイプするか、保存ボタンを押します。
   リボン周辺は画面コンテンツ幅・高さ104の判定領域です。通常はカード内部のスクロールを無効にし、カード全体の上スワイプで保存します。
   キーボード表示中だけ内部スクロールを有効にし、最下部で指を置き直した上スワイプを保存操作にします。キーボードを閉じると内部の表示位置を先頭へ戻して固定します。
   最下部に到達するまでのスクロール量は保存判定に含めません。保存中・閲覧専用ではスワイプ保存を無効にします。
   上方向64以上で保存します。リボン周辺・見出しでは上方向24以上かつ速度0.6以上のフリックでも保存できます（距離はReact Nativeのレイアウト単位）。
   カード下側はスクロールのレスポンダーを奪わず、最下部から始まるタッチの移動と終了を追跡して保存します。キャンセルされたタッチは保存しません。画面内には操作説明を追加せず、従来のスワイプ案内だけを表示します。
   判定未達では元に戻り、判定達成では元に戻さずその位置で保存を待ちます。入力不正・保存失敗時は元に戻し、エラーを表示します。
4. `PUT` の保存成功後だけ、返却された `color_code` を使って完了演出を表示します。退場アニメーションはネイティブドライバーで320ms、画面の高さに応じて上へ移動します。
   新規・更新ともに完了後は上部の見出しと戻る矢印を隠し、成功メッセージと「本の詳細へ」「続けて他のページの感想も書く」を中央に表示します。
   続けて記録すると同じ本・読書回の入力をリセットし、見出しと戻る矢印を再表示します。
   失敗時は入力を保持し、エラーを表示して再試行できます。保存中の二重送信は防止します。
5. 「本の詳細へ」で戻ると詳細を再取得し、保存されたページに応じた進捗を表示します。

詳細の「自分のしおり」は `GET /books/{bookId}/reviews?iteration={iteration}&limit=100&offset=0`
をページングして取得します。保存後に詳細へ戻ると、感想と各しおりの色を再取得します。
解析状態とsourceから、実AIによる色・AI未接続の仮色・解析待ち・解析失敗を区別します。
同じ感想や似た感情の解析では同じ色になる場合があります。色をランダムには変更しません。
感情グラフの実データ化は未対応です。
ネタバレ設定・他の人への公開は未対応です。

### 自分のしおりの閲覧・編集

数直線の点または感想行をタップすると、本ID・読書回・ページ番号を渡して栞を開きます。
ページ番号の再入力なしで感想と色を自動取得します。読書中の最新回は編集でき、
読了済み・過去の読書回は閲覧専用です（保存ボタン・スワイプ保存・本文編集は無効）。

数直線は左端がAPIの `current_page`（読んだ最遠ページ）、右端が0ページです。
近接した栞は最低56pxの間隔を確保するよう区間を伸ばし、この数直線部分だけを横に
スクロールできます。このため画面上の距離は厳密なページ比率ではありません。
タイムラインは常に全件表示し、その下の感想行はページ順で5件ずつ表示します。
9件なら「1/2」「2/2」に分け、「前へ」「次へ」で切り替えます。

関連テストは `node --test tests/bookmark.test.cjs`、型チェックは `npm run typecheck` で実行できます。

## ログイン

起動時にログインを復元し、未ログイン時はログイン・登録・メール確認・パスワード再設定画面だけを表示します。
認証画面には下部ナビゲーションを表示しません。APIはJWTを自動付与し、401時に一度だけ更新して再試行します。
アカウント画面の名前・メールはログイン中の情報を表示します。設定画面からログアウトできます。
登録・再設定のパスワードは12〜128文字です。メールに届いた確認トークンを画面へ貼り付けます。

Web版のアクセストークンはメモリ、リフレッシュトークンはAPIのHttpOnly Cookieに保存します。
Webの本番配置ではフロントとAPIを同一サイトに置いてください（例: `app.example.com` と `api.example.com`）。
CookieはSameSite=Laxで、ブラウザの異なるサイトへのCookie制限を前提とした設計です。
開発時はバックエンドを `APP_ENV=development` にし、フロントとAPIで `localhost` / `127.0.0.1` を混在させないでください。
スマホ版はリフレッシュトークンを `expo-secure-store` に保存します。依存関係の追加後は `npm install` を行い、
独自の開発ビルドを使っている場合はネイティブアプリを再ビルドしてください。
SMTP・秘密鍵・マイグレーションは [認証設定](../fastapi/docs/authentication.md) を参照してください。
