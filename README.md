# Re: Read

![ロゴ](./docs/images/Re_Read.png)

## 製品概要

**読書の途中で生まれた気持ちを、色のついた「しおり」として残す読書記録アプリです。**

読み終わった本の評価だけでなく、「どのページで、何を感じたか」を短い感想と色で記録します。本棚・ページごとのしおり・感情の可視化を通して、自分の読書体験を振り返れます。

### 背景(製品開発のきっかけ、課題等）

本を読んでいると、心が動く場面や、誰かに伝えたくなる一文に出会います。しかし、読了後にまとめて感想を書こうとすると、そのときの細かな気持ちやページを忘れてしまいがちです。

長いレビューを書く負担を減らし、読書を中断しすぎずに、その瞬間の感情を残したい。そんな課題に対して、紙の本にしおりをはさむような感覚で使える記録体験を目指しています。

### 製品説明（具体的な製品の説明）

1. Google Booksでタイトルを検索し、読みたい本・読んでいる本を自分の本棚へ追加します。
2. 読書中の本を開き、ページ番号と1〜140文字の感想を入力します。
3. 保存ボタン、またはカードを上にスワイプする操作で「しおり」を保存します。
4. Jevによる感情分析を設定した環境では、感想から8種類の感情の強さを分析し、その結果をしおりの色に変換します。
5. 本の詳細画面で、ページ順のしおりや感想、読書進捗を確認できます。さらに、同じ本に対する解析済み感想の集計から、感情の傾向を可視化します。

現在は開発段階です。読書APIの利用には、認証設定・メール送信設定・DBマイグレーションを適用し、登録後にメール確認とログインを行ってください。JevのAPIキーが未設定の場合はモック分析となり、実際の感情分析とは区別して表示します。起動方法と設定の詳細は、[フロントエンドのREADME](./frontend/README.md)・[バックエンドのREADME](./fastapi/README.md)を参照してください。

### 特長
#### 1. 読書中の気持ちを、ページと一緒に残せる

感想は1〜140文字。短い言葉で記録できるため、読了を待たずに、その場で感じたことを残せます。同じ読書回・同じページのしおりは更新でき、読了済み・過去の読書回の記録は閲覧専用で扱います。

#### 2. 感情が、しおりの色になる

喜び・信頼・恐れ・驚き・悲しみ・嫌悪・怒り・期待の8感情を分析し、独自の変換ロジックで色を生成します。ランダムな色付けではなく、感情の方向・まとまり・強さを色相・彩度・明るさへ反映します。

#### 3. しおりをたどって、読書体験を振り返れる

ページ上の位置を示すタイムラインと感想一覧から、しおりを開けます。本の詳細では、全ユーザー・全読書回のJev解析済み感想を集計した8感情の平均値と色も表示し、その本がどのような感情を生んでいるかを確認できます。

### 解決出来ること

* 読了後には忘れてしまう、読書中の小さな気づきや感情をページ単位で残せます。
* 長文レビューを書く代わりに、短い感想で読書記録を続けられます。
* 感想の文章だけでなく色も手がかりにして、印象に残った場面を振り返れます。
* 本棚と読書進捗をまとめて確認し、今読んでいる本の記録へすぐに戻れます。

### 今後の展望

* 自前のメール・パスワード認証、メール確認、パスワード再設定で、ユーザーごとの読書記録を管理します。設定は [認証ドキュメント](fastapi/docs/authentication.md) を参照してください。
* 他の人のしおりの閲覧・公開範囲・ネタバレ制御を実装し、読書の進み具合に合わせて感想に触れられるようにします。
* 現在サンプルとなっている本の編集画面を実際の保存処理につなぎ、本棚管理を充実させます。
* ページに沿った感情の変化や再読時の違いを比較できるようにし、読書体験の振り返りを深めます。

### 注力したこと（こだわり等）

* **「しおりをはさむ」操作感と色によるフィードバック**：上方向のスワイプで保存でき、保存成功後にだけ返却された色で完了演出を表示します。失敗時は入力を保持し、再試行できるようにしています。
* **記録と分析の信頼性**：感想本文を先に保存し、分析に失敗しても文章が失われないようにしています。分析待ち・失敗・モック・実AIを区別し、更新前の古い分析結果が新しい感想へ反映されないようにしています。

## 開発技術
### 活用した技術
#### API・データ

* **Google Books API**：書籍のタイトル検索と、著者・ページ数・表紙などの書誌情報の取得に利用しています。
* **Jev（TypeSafe SDK）**：感想文に表れた8感情を、それぞれ独立した強度として分析します。
* **PostgreSQL**：ユーザー、本棚、読書回、感想、分析結果を保存します。Google Books由来の書誌情報はIDのみを永続化します。
* **Redis**：Google Booksの書誌情報を取得から30日間キャッシュし、繰り返しの外部API呼び出しを減らします。

#### フレームワーク・ライブラリ・モジュール

* **Expo / React Native / React / TypeScript**：スマートフォン向けUIと画面遷移、型付きのAPIクライアントを実装しています。
* **React Native Animated / react-native-svg / Expo LinearGradient・Blur**：スワイプ後の演出、感情の可視化、グラデーションや半透明のUIに利用しています。
* **Python / FastAPI / Pydantic**：読書記録・書籍検索・感情分析のAPIと入力検証を実装しています。
* **SQLAlchemy / psycopg / Alembic**：データアクセスとデータベースのスキーマ管理に利用しています。
* **httpx / typesafe-sdk / redis**：外部APIやキャッシュとの接続に利用しています。
* **Docker Compose / uv**：バックエンド・PostgreSQL・Redisの開発環境とPython依存関係を管理しています。
* **pytest / Ruff / Node.js標準テストランナー / TypeScript**：バックエンドのテスト・静的チェック、フロントエンドのテスト・型チェックに利用しています。

#### デバイス

* **iOS / Androidスマートフォン**：Expo Goを利用してアプリを起動する想定です。
* **開発用PC**：Expoの開発サーバーと、Docker Composeによるバックエンド・データベース・キャッシュを実行します。

### 独自技術
#### ハッカソンで開発した独自機能・技術

* **8感情からしおりの色を生成する変換ロジック**：感情ベクトルを2次元へ投影し、感情の方向を色相、まとまりを彩度、最も強い感情の強度を明るさに対応させます。感情が表れない場合はグレーを返します。実装は[感情モデル・色変換](./fastapi/src/backend/analysis/domain/emotions.py)と[Jev分析器](./fastapi/src/backend/analysis/infrastructure/jev.py)にあります。
* **ページ単位・読書回単位のしおり記録**：本・読書回・ページを指定して感想を保存・更新し、過去の記録と現在の読書を分けて扱います。保存と分析の整合性を保つ処理は[アプリケーションサービス](./fastapi/src/backend/reviews/application/service.py)にあります。
* **スワイプ保存と、記録をたどるUI**：保存状態と連動したアニメーションに加え、近接するしおりを選びやすくする横スクロールのタイムラインを実装しています。実装は[しおり入力画面](./frontend/src/components/templates/BookmarkScreen.tsx)と[しおりタイムライン](./frontend/src/components/molecules/BookmarkTimeline.tsx)にあります。
* **本ごとの感情の可視化**：本の解析済み感想を集計した8感情の強度と色を表示し、詳細画面のアクセントにも反映します。実装は[感情分析カード](./frontend/src/components/organisms/EmotionAnalysisCard.tsx)と[本の詳細画面](./frontend/src/screens/books/BookDetailScreen.tsx)にあります。

バックエンドは認証認可・蔵書・感想・AI分析の4コンテキストで構成しています。責務と連携は [コンテキスト設計](fastapi/docs/contexts.md) を参照してください。
